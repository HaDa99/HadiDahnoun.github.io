## The assignment

The goal of this assignment is to learn how to gain new insights exploratively with the help of a computer, record them as conjectures and, ideally, prove them rigorously. The object of study is the **coprime graph** *T(n)*.

*T(n)* has *n* vertices, numbered 1, …, *n*. Two different vertices *x* and *y* are joined by an edge exactly when the numbers *x* and *y* are coprime, i.e. gcd(*x*, *y*) = 1. Example for *n* = 9: vertex 1 is connected to all other vertices, vertex 2 to vertices 1, 3, 5, 7, 9, vertex 3 to vertices 1, 2, 4, 5, 7, 8, vertex 4 to vertices 1, 3, 5, 7, 9, and so on.

Some structural properties of (unlabelled) graphs show up in the algebraic properties of their adjacency matrix. Only properties that do not depend on how the rows and columns are indexed are interesting here. One example is the **rank** of the adjacency matrix. Complementary to it, the **nullity** of an *n*×*n* matrix with rank *r* is *n* − *r*. A graph is called *null* if its nullity is greater than zero. Almost no graphs are null, so it is interesting to find classes of null graphs and to predict, or even explain, their nullity from their structure.

The tasks:

- **a)** Determine the rank and nullity of the adjacency matrix for as many graphs *T(n)* as possible, for increasing *n*.
- **b)** Find a pattern in how the rank develops with *n*. Use the prime factorization of *n* to predict how the rank of *T(n)* differs from that of *T(n−1)*.
- **c)** For some example graphs *G* with *n* vertices and adjacency matrix *A*, compute *y* = *Ax* for an arbitrary vector *x* ∈ ℝⁿ. Alternatively, write the values of *x* on the vertices of *G* and add up, for each vertex, the values of all its neighbours. Compare the result with *y*. What do you notice? Find a general explanation.

## Part A: Computing rank and nullity

A Python script builds the adjacency matrix of *T(n)*:

1. **Matrix initialization:** *A* starts as an *n*×*n* matrix of zeros, i.e. a graph with *n* vertices and no edges.
2. **Iterating over vertices:** the script loops over all pairs of vertices *i* and *j* from 1 to *n*, which correspond to the integers 1 to *n*.
3. **Edge condition:** for each pair (*i*, *j*) it checks whether gcd(*i*, *j*) = 1. If the numbers are coprime and *i* ≠ *j*, the entry *A*[*i*−1][*j*−1] is set to 1, which represents an edge between vertices *i* and *j*.

```python
def create_adjacency_matrix(n):
    A = np.zeros((n, n), dtype=int)
    for i in range(1, n + 1):
        for j in range(1, n + 1):
            if i != j and gcd(i, j) == 1:
                A[i-1][j-1] = 1
    return A
```

Using the symmetry of the matrix:

```python
def create_adjacency_matrix(n):
    A = np.zeros((n, n), dtype=int)
    for i in range(1, n + 1):
        for j in range(i + 1, n + 1):
            if gcd(i, j) == 1:
                A[i-1][j-1] = 1
                A[j-1][i-1] = 1  # use symmetry
    return A, n
```

Rank and nullity were then also computed in Python with NumPy. The script was run for *n* = 10, *n* = 100 and *n* = 1000.

## Part B: A pattern for the rank

The plots show that the rank of the adjacency matrix grows roughly linearly with *n*. In general, the number of linearly independent rows increases as more vertices (numbers) are added, since each new vertex *n* brings edges to all vertices coprime to *n*.

To analyse how the rank changes from *T(n−1)* to *T(n)*, and how this relates to the prime factorization of *n*, the graphs for *n* = 1 to 18 were tabulated:

| n | Prime factorization | Rank |
|---|---|---|
| 1 | 1 | 0 |
| 2 | 2 | 2 |
| 3 | 3 | 3 |
| 4 | 2·2 | 3 |
| 5 | 5 | 4 |
| 6 | 2·3 | 5 |
| 7 | 7 | 6 |
| 8 | 2·2·2 | 6 |
| 9 | 3·3 | 6 |
| 10 | 2·5 | 7 |
| 11 | 11 | 8 |
| 12 | 2·2·3 | 8 |
| 13 | 13 | 9 |
| 14 | 2·7 | 10 |
| 15 | 3·5 | 11 |
| 16 | 2·2·2·2 | 11 |
| 17 | 17 | 12 |
| 18 | 2·3·3 | 12 |

A new prime connects to all other vertices except itself, which typically increases the rank.

The rank also increases when the structure of the prime factorization changes in a new way. Up to *n* = 18, apart from primes, the rank grows when a **new combination of prime factors** first appears:

- *n* = 6 (first occurrence of 2·3) → rank rises to 5
- *n* = 10 (first occurrence of 2·5) → rank rises to 7
- *n* = 14 (first occurrence of 2·7) → rank rises to 10
- *n* = 15 (first occurrence of 3·5) → rank rises to 11

The rank does **not** increase:

- when *n* is a power of a prime that already occurs (e.g. 4 = 2², 8 = 2³, 9 = 3², 16 = 2⁴);
- when *n* is composed only of prime factors and combinations that are already present. For *n* = 18 = 2·3·3, for example, the rank stays the same, because the connectivity caused by the primes 2 and 3 and their combination 2·3 is already represented in the matrix.

An illustration for *n* = 9: whether a number is coprime to 3 or to 9 depends only on whether it is divisible by 3. So vertices 3 and 9 are connected to exactly the same set of vertices (those not divisible by 3), and their rows in the matrix are identical.

**Conclusion.** The rank of the adjacency matrix typically increases when *n* introduces either a new prime or a new combination of primes that was not yet part of the matrix structure. Such new primes or combinations create new, linearly independent connection patterns that extend the existing structure. The resulting conjecture:

```
Rank(n) = (number of primes ≤ n) + (number of prime-factor combinations ≤ n)
```

Applied to *n* = 17:

- primes ≤ 17, counting 1 as in the original (1, 2, 3, 5, 7, 11, 13, 17): 8
- prime-factor combinations ≤ 17 (2·3, 2·5, 2·7, 3·5): 4
- → Rank(17) = 8 + 4 = 12

## Part C: What *y* = *Ax* means

**Interpreting the matrix-vector product.** Each row *i* of *A* describes how vertex *i* is connected to all other vertices *j*:

```
a_ij = 1   if gcd(i, j) = 1 (and i ≠ j)
a_ij = 0   otherwise
```

The *i*-th component of *y* is the dot product of row *i* with *x*:

```
y_i = Σ_{j=1..n} a_ij · x_j
```

Since *a<sub>ij</sub>* = 1 exactly for neighbouring vertices and 0 otherwise, this is the sum of *x<sub>j</sub>* over all vertices *j* connected to *i*. Adding up the neighbour values by hand gives exactly the same expression:

```
y_i = Σ_{j : gcd(i, j) = 1} x_j = Σ_{j=1..n} a_ij · x_j
```

So ***y* = *Ax* computes, for every vertex, the sum of the values of its neighbours.**

**Worked example for *n* = 7.**

*Step 1: the adjacency matrix of T(7).* Vertices are {1, …, 7}; an edge joins *i* and *j* when gcd(*i*, *j*) = 1:

```
      1 2 3 4 5 6 7
  1 [ 0 1 1 1 1 1 1 ]
  2 [ 1 0 1 0 1 0 1 ]
  3 [ 1 1 0 1 1 0 1 ]
  4 [ 1 0 1 0 1 0 1 ]
  5 [ 1 1 1 1 0 1 1 ]
  6 [ 1 0 0 0 1 0 1 ]
  7 [ 1 1 1 1 1 1 0 ]
```

*Step 2: y = Ax for an arbitrary vector x = (x₁, …, x₇).*

```
y1 = x2 + x3 + x4 + x5 + x6 + x7
y2 = x1 + x3 + x5 + x7
y3 = x1 + x2 + x4 + x5 + x7
y4 = x1 + x3 + x5 + x7
y5 = x1 + x2 + x3 + x4 + x6 + x7
y6 = x1 + x5 + x7
y7 = x1 + x2 + x3 + x4 + x5 + x6
```

Each *y<sub>i</sub>* is a linear combination of the neighbour values: the adjacency relation (1 for adjacent, 0 otherwise) is multiplied by the vertex values of the neighbours.

For *n* = 7, rank(*A*) = 6. The 7-dimensional output *y* is therefore confined to a 6-dimensional subspace, and indeed *y*₂ = *y*₄. A higher rank means more rows contribute independent equations to the system *y* = *Ax*, and so a greater variety of possible outputs.

The rank of *A* determines **how many independent neighbourhood sums** in the graph actually carry **new information**. The higher the rank, the more independent the computations in the system *y* = *Ax*.
